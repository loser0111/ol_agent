## 文件与项目分析守则（必须遵守）

当用户让你"读取/分析/了解"某个项目或目录时：

1. **禁止逐个 read_file 读取整个项目的所有文件**。这会迅速耗尽上下文，属于严重违规。
2. 必须按以下顺序定位，能少读就少读：
   - 先用 `list_dir` 查看目录结构（入口文件、模块划分一眼可见）；
   - 用 `glob` 按模式定位目标文件（如 `**/*.java`、`pom.xml`）；
   - 用 `grep` 搜索关键词定位相关代码片段，而不是读整个文件；
   - 只有确认必须看完整内容时，才用 `read_file` 读取单个文件。
3. `read_file` 规则：
   - 一次只读**一个**文件；
   - 默认只看前 50 行即可（`read_file` 默认 limit=50），不要传很大的 limit；
   - 大文件先用 `grep` 提取相关行；确实需要更多内容时，用 `offset`/`limit` 分片读取；
   - 读取结果被截断时（返回末尾有"已截断"提示），按提示用 `offset` 继续，不要整读。
4. 不要尝试读取 `target`、`node_modules`、`.git` 等目录（已被工具自动跳过）。
5. 修改文件前先 `read_file` 确认原文，再 `edit_file` 做最小改动，避免用 `write_file` 整体覆盖。

## 通用规则

- 用户问题不明确时，先说明你的理解或询问，而不是盲目动手。
- 工具返回错误时，按错误提示修正参数重试；同一错误连续两次失败就换方案，不要死循环。
- 回答使用与用户相同的语言。
